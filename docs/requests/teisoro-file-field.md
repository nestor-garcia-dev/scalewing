Scalewing request from Teisoro.

Status: released in `@scalewing/react` 1.42.0 (PR #200; accepted 2026-10-19; Teisoro F-014-S03 "Scalewing: file picker, PDF viewer, Markdown view, blue count", task 2610; the training library inventory's row 18 and §2; plan approval under the owner's F-014 delegation of 2026-10-19).
Renderer: react
Missing surface: `FileField`, one file chosen with the system picker or dropped on the field.
Why Box/Stack/Inline/Card/Text/Button/Field cannot do this: the training boards' Add, the add-a-language sheet and the page editor's cover photo choose a file: an empty field that says "Choose a PDF", the chosen file's name with a line about it ("4 pages · 1.6 MB · opens fine") and "Choose another", and a refused file's error. `Field` wraps a native `<input type="file">`, which draws the browser's own button and "No file chosen" (user-agent chrome the visual language rules out), takes no drop, and cannot show the consumer's line about the file.
Existing surface this might already be: `Field` with an `<input type="file">` (browser chrome, no drop, no chosen state); `Button` opening a hidden input (the picker, but no frame, drop, chosen state or Field labelling).
Workaround I almost used: a hidden input and a `Button` in a Teisoro composite, with a hand-made frame, which Teisoro cannot style.
Teisoro use: the PDF step of Add, the language sheet's file, the page editor's cover photo, "Add a photo" and "Open a .md or .txt file" (S05).
Proposed API (inventory): choose or drop a file, the accept list, the chosen file's name and a detail line, Choose another, error text, disabled; works with Field labelling; no upload logic (the consumer gets the `File`).

## Accepted API (2026-10-19)

- `FileField` (`FileFieldProps`, `FileFieldValue`):
  - `label: string`, `labelVisuallyHidden?`, `description?` and `error?`, drawn and announced as `Field`'s (the error a polite live region in place of the hint and in the button's description, the frame's edge in the danger colour, `Mark` in forced colours; the buttons carry no `aria-invalid`, which the button role does not support);
  - `accept?: string`, the native `accept` list the picker offers;
  - `value?: { name: string; detail?: string } | null`, the chosen file as the consumer shows it;
  - `onChange(file: File)`, called with the file chosen or dropped (the first of several);
  - `chooseLabel: string` ("Choose a PDF"), `changeLabel: string` ("Choose another"), `dropLabel?: string` ("or drop it here");
  - `icon?: ReactNode`, a consumer mark before the chosen file's name, hidden from assistive technology;
  - `disabled?` and `id?`.
- Empty: one wide zone on the subtle fill, a hairline frame at the medium radius, a native button named by the label and its words ("Field guide Choose a PDF or drop it here"), the choose words in the text colour at label weight (the accent falls under 4.5:1 on the subtle fill in eight palette and scheme pairs), the drop words muted after them and left out on a coarse pointer, at least 44 px tall.
- Chosen: a row on the surface with the icon, the name (label weight, wrapping) over the muted detail, and a neutral `Button` named by the label and `changeLabel`, described by the name, the detail and the hint (or the error); on a narrow column the button wraps under the name at the row's end.
- Either button opens the system picker through a hidden native input that is never a Tab stop; the input is cleared after each choice, so the same file again is a change. When a choice or a drop swaps the zone for the chosen row (or back) while focus is in the field, focus moves to the button now there; focus the person moved elsewhere first (an answer that comes later) is never taken back, and a drop from elsewhere moves no focus. A blur while the window itself is away (the system picker is open) is not the person leaving the field. A file dropped on the frame calls `onChange`; a file dragged over draws the accent edge and the accent tint (`Highlight` in forced colours), with every word on the tint in the text colour (4.5:1 in every palette); text or links dragged over are ignored.
- It never reads, checks or uploads the file, and a dropped file is not filtered by `accept`: the consumer checks what it gets and says why in `error`.
- `disabled` blocks the picker, refuses a dropped file (the browser does not open it) and ends a drag in progress, dashes the frame and greys the empty zone's words and the change button (`disabledAppearance="neutral"`, never faded); a chosen file's name (in the text colour) and detail (muted, 4.5:1 on the surface in every palette) stay readable, as a disabled `Field` keeps its value readable.
- A file dragged over an invalid field draws the drag's accent edge, not the error's, while it is over the field.
- An empty `label`, `chooseLabel` or `changeLabel`, a blank `dropLabel`, or a `value` with no name or a blank detail throws a `RangeError`.
- No new tokens, layers or dependencies. New classes `sw-file-field`, `sw-file-field-frame`, `-empty`, `-chosen`, `-dragging`, `-disabled`, `-zone`, `-choose`, `-drop`, `-icon`, `-file`, `-name`, `-detail`.

### Differences from the boards (Teisoro D-2)

- The empty zone's "Choose a PDF" is in the text colour at label weight, not the boards' blue link colour: the accent falls under 4.5:1 on the subtle fill in several palettes.

- The refused upload's error is Field's red line under the field; the States board draws it as a tinted box above a "Choose a PDF" button. Teisoro can add a `Notice` for a longer explanation.
- The chosen row's mark is the consumer's icon (a Lucide file glyph); the boards draw a small PDF page.
