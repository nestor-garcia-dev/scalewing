Scalewing request from Teisoro.

Status: released in `@scalewing/react` 1.34.0 (PR #157; accepted 2026-10-12; Teisoro F-011 task 2185; plan approval under Teisoro decisions O-1 to O-4 and D-1). Teisoro's acceptance review listed it as gap 17, "Whole-row press for search results (NsfPay1)".
Renderer: react
Missing surface: a whole-row press on `TableRow` for a row's one action, and a cell action drawn as the cell's text. An extension of `TableRow` and `TableCell`, not a new component.
Why Box/Stack/Inline/Card/Text/Button/Field cannot do this: the product owner, at the cash check's customer search: "on these tables, can we make the entire row clickable instead of just the link. that would help speed up the process for the cashiers". Teisoro's pick-from-a-list tables (the cash check's customer results, the bounced check's "who owes" search, the NSF list) put the action on the name only, an accent ghost `Button`, so a cashier must hit the name. The boards (StepCheck1a, NsfPay1) draw the name as bold text with the whole row pressable. A `Button` cannot wrap a `tr`, a row `onClick` in product code is not reachable by keyboard and gives no hover or pressed state, and Teisoro owns no CSS (no cursor, no row fill, no button reset).
Existing surface this might already be: `TableRow selected` (marks, does not press); `TableCell sort` (a button in the header's text style, header only); `Box link="quiet"` (a link in the text colour at weight 600, but a pick is a press, not a navigation); fantasy-football's declined `TableRow interactive` (`fantasy-football-table-row-interactive.md`: a pointer cursor alone, which hid nested buttons; here the row has one action and no other control, and the whole row does press it); the native `TableRow onPress` (`futmas-table-row-press.md`).
Workaround I almost used: leaving the name as the only target (shipped, owner asked to change it); a product `onClick` on the row with no hover, pressed or keyboard state.
Teisoro use: `CustomerSearch` (cash check StepCheck1a/StepCheckSaved, NsfFromCheck), the bounced check's `WhoOwes` (NsfPay1), the NSF list's rows.
Proposed API: `TableRow pressable` (boolean, opt-in) and `TableCell onPress` (a body cell's text as the row's action button).

## Accepted API (2026-10-12)

- `TableRow pressable` (default `false`): generated class `sw-table-row-press`. A plain primary pointer press anywhere on the row activates the row's action, its first link or button (`a[href]`, `button`), with `click()`, so it is the action's own handler that runs (a `TableCell onPress`, a router link's `onClick`). Left alone: a press with Alt, Ctrl, Meta or Shift, a non-primary button, a press another handler already took (`defaultPrevented`), a press on any other control in the row (links, buttons, form fields, labels, `summary`, editable text, the `button`, `link`, `checkbox`, `switch`, `menuitem` and `option` roles, anything in the tab order), a press that ends a text selection intersecting the row (text stays selectable), and a row whose action is disabled (`disabled` or `aria-disabled="true"`) or missing. A consumer `onClick` still runs, once per press (not again for the click handed to the action). Each click of a double click presses the action, as a native button's would. Keep one control in the row: the first link or button takes the row's press. The row is not a control: no role, no `tabindex`, no nested-interactive structure; keyboard and assistive technology users reach the action itself (one tab stop, its own name).
- Looks: the pointer cursor on the row; the quiet grey fill (`quietFill`, the muted colour at 16 %) on its cells while it is hovered (only on a pointer that hovers), pressed (`:active`) or while its action has keyboard focus (`:has(:focus-visible)`), and its `sw-table-action` underlined while hovered. Forced colours drop fills, so the row is outlined in `Highlight` (the focus ring width, inset) while hovered or keyboard focused.
- `TableCell onPress` (body `td`, or a row header `th`): the cell's children become a native `<button type="button" class="sw-table-action">` in the cell's own text style (colour, size, alignment inherited; no fill, border or padding) at weight 600, the label weight, as `Box link="quiet"` (weight, not colour, sets it apart); underlined on hover and keyboard focus, the accent focus ring; `ButtonText` in forced colours. Pair it with `TableRow pressable`. A non-function `onPress` or one on a sortable header (`sort`) throws a `TypeError`.
- Works inside the table's `ScrollRegion` and at a phone's width (no layout change: fills and outlines take no space). On touch, `:active` flashes the fill during a tap (seen in the gallery's mobile emulation; not checked on a physical phone).

Evidence: `table-press.test.tsx` (the cell button, its name, class and press; a row header; plain cells; the failures; the row class and no role or tab stop; presses anywhere else, once; a link action; consumer `onClick`; modifier keys and a secondary button; other controls; a handled press; a text selection in the row and one elsewhere; a disabled or `aria-disabled` action; a row without an action; `rowPressAction` directly; the generated rules); gallery "Table" ("Rows picked by a press": three species picked by a press on any cell); `apps/gallery/e2e/table-press.spec.ts` on desktop-en, mobile-es and forced-colors (one button per row and none on the row, weight 600 in the cell's colour and size, axe on the table with no violations, a press on another cell and on the far figure picks, a drag selection inside a cell selects text and picks nothing, Shift+press left alone, hover fill or forced-colours outline with the action underlined, the keyboard focus ring with the row filled and Enter picking, no sideways page scroll).
