Scalewing request from Teisoro.

Status: implemented on `claude/project-thread-1c7nzp`; pending review, merge and a `@scalewing/react` minor release. The product owner approved the work on 2026-09-24 up to a merge in Scalewing; do not version, tag or publish until he says so.
Renderer: react
Missing surface: `columnSpan` on `Box` (and so on every Box-based component), covering several columns of the `Grid` the box sits in. Generated classes `sw-grid-span-1`, `-2`, `-3`, `-4`, `-6`.
Why Box/Stack/Inline/Card/Text/Button/Field cannot do this: `Grid` (`teisoro-grid.md`) only makes equal-width columns (`columns` 1, 2, 3, 4 or 6, `columnsBelow`), so two children always split a row in half. Nothing lets one child cover two of three columns, and Teisoro owns no CSS, inline `style` or widths (`docs/operations/scalewing-consumer.md`).
Existing surface this might already be: `Grid` (equal columns only), `Split` (a resizable start pane with a drag separator, not a fixed proportion that stacks on a phone), `Inline` (content-width children).
Workaround I almost used: keeping equal columns (the accepted interim layout), or an inline `gridTemplateColumns: '2fr 1fr'`.
Teisoro use: owner decision D-9 on the check-cashing page (PR #3 review, 2026-09-24; Teisoro task 909, `docs/design/check-cashing/README.md`). `CheckCashingPage` renders `<Grid columns={2} columnsBelow={{ md: 1 }} gap={4}>` with the form first and the company lookup panel second. The form should be about twice the panel's width above `md`, with the panel under the form on a phone.
Proposed API: `columnSpan?: 1 | 2 | 3 | 4 | 6` on `BoxProps` (type `GridColumnSpan`, props type `ColumnSpanProps`), mapped to `sw-grid-span-<n>` (`grid-column: span <n>`). The 2:1 page is `<Grid columns={3} columnsBelow={{ md: 1 }} gap={4}><Stack columnSpan={2} gap={4}>…</Stack><CompanyLookupPanel /></Grid>`.
Behavior and failure boundary: presentation only; it applies to a direct child of a `Grid`. A span is capped at the columns its grid has at the current width (`:where(.sw-grid-cols-2) > .sw-grid-span-3 { grid-column: span 2; }`, restated under the same `md` query for every `sw-grid-cols-below-md-*`), so it never creates an implicit column and `columnsBelow` alone decides the phone layout. A span outside the catalog throws a `RangeError`, as a column count does. Reading order and focus order follow the DOM; a span does not reorder children.

Design notes:

- Reuses `Box` like `hideBelow`/`hideFrom` rather than adding a `GridItem` wrapper, so the form keeps its own `Stack` and no extra element is rendered.
- No `spanBelow`: capping at the phone column count covers "stack below `md`" without a new responsive class family. ADR 0010 asks for its own ADR before further responsive classes; the cap rules only target the existing `sw-grid-cols-below-md-*` classes under the same `md` query, with no new class name. A per-breakpoint span needs that ADR and a filled request first.
- No arbitrary templates (`2fr 1fr`): the span catalog is the column catalog, so the rule in `teisoro-grid.md` stands.
