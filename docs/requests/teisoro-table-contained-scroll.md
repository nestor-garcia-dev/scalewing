Scalewing request from Teisoro.

Status: accepted 2026-10-13 for `@scalewing/react` 1.38.0 (Teisoro F-012-S03, release M1 "tables that hold a period", item 1; the manager views inventory's row 15 and risk 2; plan approval under Teisoro decisions O-1, O-3, D-1 and D-6).
Renderer: react
Missing surface: a `Table` of bounded height whose rows scroll inside the table's own region, with the header pinned to the region's top and a sticky `TableFooter` total pinned to its bottom. An extension of `Table` (`maxHeight`), not a new component.
Why Box/Stack/Inline/Card/Text/Button/Field cannot do this: the owner's rule (Teisoro O-3, D-6) is that a table which adds things up scrolls instead of paging, so the total over the whole filtered period stays in view. The boards (ReportsRegisters' Closeouts, 14 rows; ReportsOverview's Days) draw the table at a bounded height with its header and total pinned and the rows scrolling between them ("14 closeouts · the table scrolls · the total is all 14"). Today `stickyHeader` and `TableFooter sticky` pin to the page while the table fits its width, or to a region that never scrolls vertically; nothing bounds the region's height, and Teisoro owns no CSS.
Existing surface this might already be: `Table` `stickyHeader` and `TableFooter` `sticky` (they pin to the page, `teisoro-table-footer.md` and `teisoro-table-sticky-page.md`); the private `ScrollRegion` (scrolls a wide table sideways and shades its inline edges), which this reuses.
Workaround I almost used: a `Box` with an inline `max-height` and `overflow: auto` round the table (inline style in Teisoro, and the region would be a second scroll box with no name, no keyboard stop and no shade); paging a table with a total (the owner ruled it out).
Teisoro use: `ReportTable` (F-012 composite) for every report table with a total: Closeouts, Days, Nights, the vault each day, the checks, Audit differences.
Proposed API (inventory): `maxHeight?` (a token size or rows), the region focusable and named, a shade at the edge that has more.

## Accepted API (2026-10-13)

- `Table` `maxHeight?: TableMaxHeight`, where `TableMaxHeight` is `{ rows: number }` (exported). Default: none, the table is as tall as its rows, exactly as before.
- **How the height is expressed: a row count.** A table's natural unit is its rows, and the boards bound theirs by rows (the Closeouts board's region is twelve 44 px rows). A count follows `density` and the type scale on its own, needs no new size token (Scalewing has no height scale, and a spacing step or a rem length would be a number the consumer has to work out from row heights), and keeps px out of the consumer. The object form leaves room to add another unit later without a breaking change, and reads unambiguously at the call site (`maxHeight={{ rows: 12 }}`, never "12 what?").
- The region (`sw-table-wrap`) takes `sw-table-bounded` and the count as a custom property (`--sw-table-max-rows`, a unitless number, the way `BarChart` hands its fill ratio). The generated CSS sizes it as that many single-line body rows plus one header row when the table has a `thead` and one footer row when it has a `tfoot`, each from the measures the cells are drawn with, now shared in `css/css-table-metrics.ts` by the cell rules, the sort button and the bound, so they cannot drift apart: a body row is the body line (25 px) plus the cell's block padding twice plus its 1 px rule, a pinned header row the caption line (18 px) plus the padding twice (its rule is drawn inside it), a header with sort buttons the button's least height instead (the xs control; the 44 px touch target on a coarse pointer), and `density="compact"` swaps the padding. Rows taller than one line (two-line cells, controls), a second header row or footer row (not counted) and a horizontal scrollbar that takes room (classic scrollbars) show fewer rows. Printed, a bounded region shows every row (`max-height: none`).
- The region already scrolls (`overflow: auto`); with a bounded height its rows scroll in it, so the sticky header group (`thead`, `top: 0`) pins to the region's top and a `TableFooter sticky` (`bottom: 0`) to its bottom, its nearest scroll box. A non-sticky footer scrolls with the rows as the table's last row.
- **Opt-in only; page pinning unchanged.** A bounded region is never marked `sw-scroll-fits`, so the page-pin rule (`css-table-page-pin.ts`, Teisoro F-011 D-140 and D-144: a fitting region with a sticky footer or `stickyHeader="page"` stops being a scroll box) never applies to it; that rule's text is unchanged. A bounded table keeps its header pinned to the region, so `stickyHeader="page"` or `false` with `maxHeight` throw a `RangeError`, as do a value that is not `{ rows }` and a row count that is not a whole number from 1.
- The region stays a keyboard stop (`tabIndex=0`, `role="group"`) named after the table (`aria-label` or `aria-labelledby`), so the rows scroll from the keyboard (arrows, Page Up/Down, Home/End) without scrolling the page.
- **Edge shade.** `useScrollOverflow` now also follows the block axis (`blockScrollOverflow` in `scroll-overflow.ts`, the same 1 px tolerance), and `ScrollRegion` marks `sw-scroll-more-top` and `sw-scroll-more-bottom` while rows are scrolled out past an edge (a region whose height follows its content never gets them). The shade is the inline edges' colour (`scrollShadeColor`, now exported from `css-scroll-region.ts`), a spacing step 5 deep, the gradient the pinned start column of a `DenominationGrid` casts. A pinned row covers the region's own edge, so it casts the shade: the header's last row extends its rule's `::before` downward into the gradient, and a sticky footer's first row extends its 2 px rule's `::before` upward into it, inside their layers, over the rows under them, with no cell moving. An edge with nothing pinned (a bounded table without a sticky footer, or without a header) shades the region's own edge with a background layer fixed to the box, under the rows as the inline shade is; top and bottom together are one rule. Only the header's last row casts it, so a header cell spanning rows from an earlier row casts none under its column. Forced colours draw no shade (the system scrollbar is the cue) and keep the rules in `CanvasText`.
- **Focus ring.** The region's ring is its own inset outline, which the pinned header and sticky footer paint over. While the region has keyboard focus, those pinned cells carry the part they cover as an inset accent line: the top of the header's first row, the bottom of the footer's last row, and the outer side of each pinned row's first and last cell, mirrored right to left. The parts are custom properties on the cell joined in one `box-shadow`, so a corner cell carries two. Forced colours drop shadows; the outline shows beside the rows there.
- Review round one (fresh Bar Raiser) added the shared metrics, the sorting header's height, the focus ring over the pinned rows, the print rule, border-box shade pseudos and an unconditional page-pin browser check.
- Generated classes `sw-table-bounded`, `sw-scroll-more-top`, `sw-scroll-more-bottom`. No new tokens, stacking layers or dependencies.
