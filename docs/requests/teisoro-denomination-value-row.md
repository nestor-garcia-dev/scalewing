Scalewing request from Teisoro.

Status: released in `@scalewing/react` 1.37.0 (PR #167; Teisoro F-011 task 2205).
Renderer: react
Missing surface: `DenominationGrid` `valueRow`: a line under a strip row giving each column's value (the money its count adds up to), with the row's total on it; and `Stepper` `aria-describedby`, so a typed count is described by its value. An extension of `DenominationGrid` (`teisoro-denomination-grid.md`, `teisoro-denomination-grid-entry.md`), not a new component.
Why Box/Stack/Inline/Card/Text/Button/Field cannot do this: the owner asked (2026-10-12) for every bill and coin count to show each column's value under its count ("$1, $5, $10, $40, blank, $300"), one shared change for every count form, and then for the values in their own row under the counts, as the vault's balance table shows a Count row and a Value row (canvas board StepCheckOpen1: a value row on the subtle fill, each value centred, blank for zero, the total bold in the Total column). A second read-only row of the grid would be a row of counts (tones, zeros, signed counts, the count's own weight), sit in the row order as a peer, and could not describe the typed count above it; a `Table` beside the grid would lose its columns and pinned labels. Teisoro owns no CSS.
Existing surface this might already be: a read-only row with `emphasis="quiet"` (its cells are counts: integers drawn with the zero label and signs, not formatted values); the `tiles` layout's `subtotal` (tiles only, a caption in a tile).
Workaround I almost used: a caption under each count (the first version of this request), which the owner replaced with the row.
Teisoro use: the shared `BillCount` composite, so every count grid (open and close the day, POS close, the drawer sheets, vault add, remove and audit, get change, change orders, the money truck, commission, voids, the cash check's bills) shows the values.
Proposed API: `DenominationGridRow.valueRow?: { label: string; cells: readonly (string | null)[] }`.

## Accepted API (2026-10-12)

- `DenominationGridRow.valueRow?: DenominationGridValueRow` (`{ label, cells }`, type exported), strip layout only. The strip renders a second table row right under the row (`tr.sw-denomination-value-row`): `label` as its row header in the label column (named "<row label> <label>", such as "Counted Value", so table navigation tells the lines apart), each `cells` entry in a `td.sw-denomination-value` centred under its count, and the row's `total` in the total column (and, on a phone, under the line's name); the row itself keeps an empty total cell. `null`, `''` or a blank string leave a cell empty. The line keeps the row's tone (so a toned total stays toned) and its `disabled`.
- The consumer formats every value: the grid does no arithmetic and no currency formatting, as before.
- Each entry count with a value is described by its value cell (`aria-describedby`, before an `error`'s message); the value is never a tab stop. Value cell ids are the grid's `useId` prefix and the cell's place (never consumer text), so they are valid id tokens and two grids never share one. A `null` `valueRow` is none.
- `StepperProps['aria-describedby']?: string`: ids that describe the count, read before the error message; a blank value is none.
- Look: the subtle fill across the line (its pinned label too), values at label size (15/20) in data weight and tabular figures, in the text colour, centred, never wrapped; the line pads a space-2 step down (space-1 below `md`), shorter than framed counts above it. A disabled row's line fades its values with the row. Strong totals and frames apply as on any row. Forced colours: `Canvas` fill, `CanvasText` values.
- Failure boundary: a `valueRow` in the tiles layout, one that is not an object, a blank `label`, or `cells` that are not one string or `null` per column (a sparse array included) throw a `RangeError`.
- Generated classes: `sw-denomination-value-row`, `sw-denomination-value`, rules in `css-denomination-value-row.ts`. No new tokens.

Evidence: `denomination-value-row.test.tsx` (the line, its total and phone total, descriptions with an error after, a read-only toned disabled line, unique ids across grids, a row without one unchanged, every failure, the generated rules after the frame), `stepper.test.tsx` (`aria-describedby`); gallery "DenominationGrid" ("Seed sacks for the aviary"); `apps/gallery/e2e/denomination-value-row.spec.ts` on desktop-en, mobile-es and forced-colors (values, centring, tabular figures, the bold total on the line, the subtle fill, contrast, the description following a press, Tab from one count to the next, no sideways page scroll, axe).
