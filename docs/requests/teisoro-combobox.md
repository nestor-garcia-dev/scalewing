Scalewing request from Teisoro.

Status: accepted 2026-10-11 for the `@scalewing/react` 1.31.0 release (Teisoro F-011-S06, release R5 "search", item 21; the redesign inventory's row 24 and risk 8). Uses the `Field` input (`teisoro-field-search.md`, item 20).
Renderer: react
Missing surface: `Combobox`, a text input with grouped suggestions, an action and an empty state.
Why Box/Stack/Inline/Card/Text/Button/Field cannot do this: the checks step (StepCheck2, 2a, 3, Blocked, Edit) and CompanyLookup pick the company on a check by typing: "LUIS PÉREZ's companies" under an empty field, "All companies" once there is text, each company with a badge ("Warning", "Blocked") and a muted line ("2 checks · last Sep 28"), a blocked company shown but not choosable, a "+ New company “acme”" action at the end, and a note ("Not here? Type the name to search every company or add a new one."). `Select` is a button listbox with no typing; `Field` has no list. Teisoro owns no CSS.
Existing surface this might already be: `Select` (`action`, no typing), `Field` with a search variant, the native `SingleSelect`.
Workaround I almost used: `Select` with `action` (inventory risk 8's fallback), losing typing and the groups.
Teisoro use: `CompanyPicker` and `CompanyLookupSheet` (`check-cashing/CompanyLookupPanel.tsx`), StepCheck2* and CompanyLookup.
Proposed API (inventory): `label`, `inputValue`, `onInputChange`, `groups: {label, options: {value,label,description?,badge?,disabled?}[]}[]`, `onSelect`, `action?: {label,onPress}`, `emptyText`, `error`, `size`. ARIA 1.2 combobox, consumer-side filtering.

## Accepted API (2026-10-11)

- `Combobox` (props `ComboboxProps`): `label` (the input's name, drawn above it unless `labelVisuallyHidden`), `inputValue`, `onInputChange(value)`, `groups: readonly ComboboxGroup[]` (`{ label?, options: readonly ComboboxOption[] }`; `ComboboxOption` `{ value, label, description?, badge?: ComboboxBadge, disabled? }`; `ComboboxBadge` `{ label, tone?: BadgeTone }`), `onSelect(value)`, `action?: ComboboxAction` (`{ label, onPress, badge? }`), `emptyText`, and `note?`, `placeholder?`, `description?`, `error?`, `required?`, `disabled?`, `size?: 'md' | 'xs'` (`comboboxSizes`).
- **Added beyond the proposal, for the boards:** `badge.tone` (the boards' Warning, Blocked and New company tags differ in colour), `action.badge` (the "New company" tag), `note` (the "Not here? …" line), `labelVisuallyHidden` (the input sits in a table cell named by its column), `listLabel` (the boards name the list "Companies", apart from the input), `countText` (announces the number of results as the person types), and the Field props `placeholder`, `description`, `required`, `disabled`.
- Pattern: ARIA 1.2 combobox with list autocomplete. The input is `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, `aria-controls` (while the list shows) and `aria-activedescendant` (the active option); the list is a `role="listbox"` named by `listLabel`, else `label`, each labelled group a `role="group"` named by its heading, each option a `role="option"` with `aria-selected` on the active one and `aria-disabled` on a disabled one; the action is the last option.
- Keyboard and pointer: typing (the list then has no active option), a press on the input, ArrowDown or Alt+ArrowDown opens; ArrowDown and ArrowUp move and wrap (from closed, they open on the first or the last); Enter or a press chooses the active option (`onSelect`) or runs the action, and closes; a disabled option is never chosen; Escape closes, and a second Escape empties the input (`onInputChange('')`); Alt+ArrowUp, Tab, a blur or a press outside closes; moving the pointer over an option makes it the active one. Keys typed into an input method are ignored. The active option is held by its value, so it stays the same option when the results change under it (a fetch), and is dropped when that option leaves them; option ids come from values. Disabling the Combobox while open closes the list for good. While open, the input is described by the `note`; `aria-expanded` is true only while a list is shown. A press in the list never takes focus from the input.
- The list: on the popover layer under the input (as Select's and ActionMenu's lists, flipping to stay on screen), at least the input's width, up to `--sw-select-max` high; glass, solid under reduced transparency; group headings in caption type; options at the md height with the label at label weight, the badge (`Badge size="sm"`) and the description in muted caption type, wrapping; the active option on the soft muted fill (`Highlight` in forced colours); a disabled option's label muted (`GrayText`); the action in the accent colour over a hairline; a hairline between options, as the boards draw it; `emptyText` shown when no group has an option (hidden from assistive technology there, since a polite `role="status"` region, always in the page, announces it, and `countText` when given); `note` muted under it all.
- The input is a `Field`'s, so `description`, `error` (polite region, `aria-invalid`, the danger border), `required` and `size` behave as on any field. The consumer filters and sets `inputValue` on `onSelect`.
- Failure boundary: a blank `label`, `emptyText`, group label, option value or label, badge label or action label; a duplicate option value; an unknown `size` or badge tone: `RangeError`. An action without `onPress`: `TypeError`.
- Generated classes `sw-combobox`, `sw-combobox-popup`, `sw-combobox-list`, `sw-combobox-heading`, `sw-combobox-option`, `sw-combobox-label`, `sw-combobox-description`, `sw-combobox-action`, `sw-combobox-empty`, `sw-combobox-note`; `openPopups` in `css/stacking.ts` gains `.sw-combobox-popup`.
- Sizes and looks on Scalewing's scale (Teisoro D-2): options 44 high (board 48) with `space-3` padding (board 14); group headings caption 13 at 600 in sentence case (board 12 at 700 in capitals with tracking); the list radius `sm` 8 (board 12), glass with the small elevation (board white with a deep shadow), at least the input's width (board a fixed 600); the active option on the muted 16% fill (board #eef4ff); the disabled option's label muted (board #aeaeb2); the input is the Field's (`xs` 28 or `md` 44; board 40 in the table cell with a 2 px accent ring); the action's label at label weight in the accent (board 15/600 accent); badges `sm` with Scalewing's tones.

Evidence: `combobox.test.tsx` (the roles and states, the groups, option content, the arrow keys with wrapping and focus kept, Enter, a disabled option never chosen, a press keeping focus, filtering, the empty text and the action, Escape twice, blur, Field props, disabled, the failures, the generated rules; the active option kept by value across new results and dropped when it leaves them; input-method keys ignored; the live region's count and empty text; the note description; Alt+ArrowDown and Alt+ArrowUp; Tab; the pointer moving the active option; closing when disabled; ungrouped options alone and beside a group; Escape inside a Dialog closing only the list; a missing action `onPress`); gallery "Combobox" ("Station": your stations under an empty field with a note, all stations as you type with a disabled one, a new-station action, a required error; a compact disabled "Ring number"); `apps/gallery/e2e/combobox.spec.ts` on desktop-en, mobile-es and forced-colors (the list under and as wide as the input, 44 rows, keyboard choice with `aria-activedescendant`, filtering, the disabled option not chosen, a press choosing with focus kept, the forced-colours `Highlight` on the active row, the pointer moving the active option, the live region's count and empty text, the empty text and the action from the keyboard, Escape twice, a press outside, the Field error, the disabled compact field).
